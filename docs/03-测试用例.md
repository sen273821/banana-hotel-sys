# 房态看板 - 测试用例

## 1. 后端单元测试

### 1.1 RoomStatusService 测试

| 用例ID | 测试场景 | 输入 | 预期结果 |
|--------|----------|------|----------|
| BE-01 | 获取看板数据-无筛选 | floorId=null | 返回所有楼层房间+统计数据 |
| BE-02 | 获取看板数据-按楼层筛选 | floorId=1 | 仅返回1楼房间 |
| BE-03 | 修改房态-合法流转(空净→在住) | roomId=1, newStatus=OCCUPIED | 状态更新成功，写入日志，触发SSE |
| BE-04 | 修改房态-非法流转(脏房→在住) | roomId=1, newStatus=OCCUPIED | 抛出IllegalStateException |
| BE-05 | 修改房态-房间不存在 | roomId=999 | 抛出NoSuchElementException |
| BE-06 | 获取房间详情-在住房间 | roomId=2(在住) | 返回入住人信息+预订详情 |
| BE-07 | 获取房间详情-空净房间 | roomId=1(空净) | 返回空assignment |
| BE-08 | 状态变更日志记录 | 任意合法变更 | room_status_log表写入operator+reason |
| BE-09 | 出租率计算 | 10间房，3在住+2预订 | occupancyRate = 50.0 |
| BE-10 | SSE推送-状态变更 | 修改房态 | 所有SSE连接收到room_status_changed事件 |

## 3. 集成测试

| 用例ID | 测试场景 | 步骤 | 预期结果 |
|--------|----------|------|----------|
| IT-01 | 完整看板加载 | 1.启动前后端 2.访问/room-status | 页面显示所有房间网格，统计数据正确 |
| IT-02 | 修改状态端到端 | 1.点击房间菜单 2.选择新状态 | 前端更新→后端处理→SSE推送→其他客户端更新 |
| IT-03 | 多用户同时操作 | 1.打开两个浏览器 2.一个修改状态 | 另一个浏览器实时看到变更 |
| IT-04 | 楼层筛选+状态筛选 | 1.选择2楼 2.观察网格 | 仅显示2楼房间 |
| IT-05 | 非法操作拦截 | 1.尝试脏房→在住 | 前端显示错误提示，状态不变 |
| IT-06 | 详情抽屉数据 | 1.点击在住房间卡片 | 抽屉显示正确的入住人信息和操作日志 |
| IT-07 | SSE断线恢复 | 1.断开网络 2.恢复网络 | 自动重连，数据同步最新状态 |
| IT-08 | 大量房间性能 | 加载200间房间 | 页面渲染时间<2秒，滚动流畅 |
