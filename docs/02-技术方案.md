## 2. 数据库设计

### 2.1 ER关系图

```
building (1) ──→ (N) floor (1) ──→ (N) room
                                        │
room_type (1) ──→ (N) room              │
                                        │
room (1) ──→ (N) room_status_log        │
room (1) ──→ (N) room_assignment ←──────┘
```

### 2.2 表结构

#### building（楼栋表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| name | VARCHAR(50) | 楼栋名称 |
| sort_order | INT | 排序 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

#### floor（楼层表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| building_id | BIGINT FK | 所属楼栋 |
| name | VARCHAR(50) | 楼层名称 |
| floor_no | INT | 楼层序号 |
| sort_order | INT | 排序 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

#### room_type（房型表）

| 字段 | 类型 | 说明 |

| id | BIGINT PK | 主键 |

| code | VARCHAR(30) UK | 房型编码 |
| icon | VARCHAR(50) | Material图标名 |
| max_guests | INT | 最大入住人数 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

#### room（房间表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |

#### room_status_log（房态变更日志）

| 字段 | 类型 | 说明 |

## 3. 后端API设计

### 3.1 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/v1/rooms/board | 获取看板数据 |
| PUT | /api/v1/rooms/{roomId}/status | 修改房间状态 |
| GET | /api/v1/rooms/{roomId}/detail | 获取房间详情 |
| GET | /api/v1/rooms/{roomId}/logs | 获取状态变更日志 |
| GET | /api/v1/rooms/board/stream | SSE实时推送 |
| GET | /api/v1/floors | 获取楼层列表 |

```json
        "roomTypeIcon": "bed",

        "assignment": null
      },
      {
        "id": 2,
        "roomNumber": "102",
        "floorId": 1,

        }

```

#### PUT /api/v1/rooms/{roomId}/status

请求体：
```json
{
  "newStatus": "DIRTY",
  "reason": "客人退房"
}
```

响应：
```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

错误响应（非法流转）：
```json
{
  "code": 400,
  "message": "不允许从[在住]转换到[预留]",
  "data": null
}
```

#### GET /api/v1/rooms/{roomId}/logs

请求参数：
- `page` (默认1) - 页码
- `size` (默认20) - 每页条数

响应：
```json
{
  "code": 200,
  "data": [
    {
      "id": 1,
      "previousStatus": "CLEAN",
      "newStatus": "OCCUPIED",
      "operatorName": "前台张三",
      "reason": "客人入住",
      "createdAt": "2026-05-13T14:00:00"
    }
  ]
}
```

#### GET /api/v1/rooms/board/stream (SSE)

事件格式：
```
event: room_status_changed
data: {"roomId":6,"roomNumber":"106","newStatus":"CLEAN","timestamp":"2026-05-14T10:30:00"}
```

### 4.2 组件交互流程

```
RoomStatusBoard.vue (页面容器)
  │
  ├── useRoomBoard() ── GET /rooms/board
  │     └── roomBoardStore (rooms, floors, summary)
  │
  ├── useRoomStatusStream() ── SSE /rooms/board/stream
  │     └── on event → 更新 roomBoardStore.rooms[]
  │
  ├── FloorFilterTabs ── @select(floorId)
  │     └── 触发客户端过滤
  │
  ├── StatusLegendBar ── 展示 statusSummary
  │
  ├── RoomGrid
  │     └── v-for room in filteredRooms
  │           └── RoomCard
  │                ├── @click → 打开 RoomDetailDrawer
  │                └── 菜单 → useRoomActions().changeStatus()
  │                           └── PUT /rooms/{id}/status
  │
  └── RoomDetailDrawer ── 展示详情+操作日志
```

### 4.3 状态管理设计

```typescript
// roomBoardStore
interface State {
  rooms: RoomVO[]
  floors: FloorVO[]
  statusSummary: Record<RoomStatus, number>
  occupancyRate: number
  selectedFloorId: number | null
  loading: boolean

```

### 4.4 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 实时通信 | SSE | 单向推送场景，比WebSocket简单，浏览器原生支持自动重连 |
| 楼层筛选 | 客户端过滤 | 酒店房间数<500，一次加载全部，避免多余网络请求 |
| 状态变更 | 乐观更新 | 先更新UI再确认服务端，提升用户体验 |
| 状态校验 | 后端状态机 | 防止非法操作，前端仅做展示层过滤 |
| 审计日志 | append-only | 只插入不更新不删除，保证完整审计链 |
