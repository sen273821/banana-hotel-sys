# 房态看板 - 需求方案

## 1. 概述

本文档描述酒店后台管理系统"房态看板"模块的产品需求。房态看板是酒店前台人员日常运营的核心工具，用于实时查看和管理所有房间的状态。

## 2. 功能范围

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 房态网格视图 | 类似酒店前台格栅，每格显示房间号、房型、状态颜色 | P0 |
| 6种房态展示 | 空净房/预留/预订占用/在住占用/脏房/停售 | P0 |
| 楼层筛选 | 按楼层/楼栋过滤房间 | P0 |
| 状态统计 | 各状态房间数量统计 + 出租率 | P0 |
| 点击查看详情 | 点击房间卡片查看当日在住/未来预订详情 | P1 |
| 快速修改状态 | 右键/菜单快速修改房态或办理入住/退房 | P1 |
| 实时更新 | SSE推送房态变更，看板自动刷新 | P1 |
| 操作日志 | 所有状态变更记录留痕 | P1 |

## 3. 房态定义

| 状态值 | 名称 | 颜色 | 说明 |
|--------|------|------|------|
| 0 | 空净房（可售） | 绿色 #16a34a | 已清洁可出售 |
| 1 | 预留 | 橙色 #f59e0b | 团队/维修保留 |
| 2 | 预订占用 | 蓝色 #3b82f6 | 已有预订未入住 |
| 3 | 在住占用 | 紫色 #7c3aed | 客人已入住 |
| 4 | 脏房（待打扫） | 红色 #dc2626 | 退房待清洁 |
| 5 | 停售（故障） | 灰色 #6b7280 | 故障/锁房 |

## 4. 状态流转规则

```
空净房 → 预留 / 预订占用 / 在住占用 / 停售
预留 → 空净房 / 停售
预订占用 → 在住占用 / 空净房（取消）
在住占用 → 脏房（退房）
脏房 → 空净房（清洁完成）
停售 → 空净房（修复完成）
```

## 5. 交互说明

### 5.1 看板主视图

- 页面顶部显示楼层筛选标签（所有楼层 / 1楼 / 2楼 / ...）
- 标签下方显示状态图例栏，每种状态用对应颜色圆点+名称+数量表示
- 主体区域为房间卡片网格，响应式布局（自动填充，最小宽度200px）
- 右上角显示出租率统计卡片

### 5.2 房间卡片

- 左侧边框颜色标识当前状态
- 卡片内容：房间号（大字）、房型名称+图标、状态标签
- 在住/预订状态额外显示客人姓名首字母头像
- 右上角三点菜单按钮，点击展开操作菜单

### 5.3 操作菜单

- 根据当前房态动态显示可用操作
- 空净房：设为预留 / 设为预订 / 设为在住 / 设为停售
- 在住房：办理退房（→脏房）
- 脏房：标记清洁完成（→空净）
- 停售房：标记修复完成（→空净）

### 5.4 详情抽屉

- 点击房间卡片从右侧滑出详情面板
- 显示房间基本信息、当前入住人信息、操作历史记录

### 5.5 实时更新

- 页面加载后建立SSE连接
- 任何房态变更实时推送到所有在线客户端
- 断线后5秒自动重连

## 6. 用户角色

| 角色 | 权限 |
|------|------|
| 超级管理员 | 所有操作 |
| 酒店经理 | 查看看板、修改状态 |
| 前台接待 | 查看看板、办理入住/退房 |
| 客房主管 | 查看看板、标记清洁完成 |

## 7. 非功能需求

- 页面加载时间 ≤ 2秒
- 状态变更响应时间 ≤ 500ms
- 支持同时在线50个管理端用户
- 支持最多500间房间的酒店规模
